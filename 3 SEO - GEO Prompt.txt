Prompt: SEO + Generative Engine Optimization (GEO)

Copy everything below the line into Cursor / Claude / ChatGPT (Agent mode with repo access). Edit the Variables block first.

Vocabulary (read this once):

SEO = classic search (Google/Bing blue links, rankings, CTR).

GEO = Generative Engine Optimization — getting your brand cited inside answers from ChatGPT, Claude, Perplexity, Gemini, Copilot, and Google AI Overviews. Not “geo-redirect by country.”

Ship two complementary systems for PRODUCT_NAME:

═══════════════════════════════════════════════════════════════════
PART B — GENERATIVE ENGINE OPTIMIZATION (GEO)
═══════════════════════════════════════════════════════════════════

Definition (use this wording in docs you create)
Generative Engine Optimization (GEO) is structuring your content and off-site
authority so AI answer engines cite PRODUCT_NAME inside the answers they generate.
Where SEO optimizes for ranked links, GEO optimizes for cited passages.

Why this is different from SEO

| Dimension   | SEO                        | GEO                                       |
| ----------- | -------------------------- | ----------------------------------------- |
| Goal        | Rank in a list             | Be named / cited in the answer            |
| Unit        | Page                       | Extractable passage (often ~40–100 words) |
| Visibility  | Positions 1–10             | Named or invisible                        |
| Discovery   | Crawl + rank               | Training data + live RAG retrieval        |
| Measurement | Rankings, organic sessions | Citation rate, share of voice per prompt  |

Two citation pathways (optimize both)

1. Training data — presence in the open web before model cutoffs (slow, compounding).
2. Real-time RAG — ChatGPT Search, Perplexity, AI Overviews, Claude with fetch
   (this is what your site changes can influence immediately).

Citation Trinity (every page must pass all three)

1. Identity — engines must disambiguate PRODUCT_NAME as one entity.
2. Extractability — a self-contained answer block matches the buyer question.
3. Corroboration — independent third parties say compatible things about you.

───────────────────────────────────────────────────────────────────
B1. Entity identity (site + knowledge graph)
───────────────────────────────────────────────────────────────────

* Freeze ONE_LINER. Same sentence on homepage, About, schema description,
  LinkedIn, YouTube, Product Hunt, G2, Crunchbase, founder bios, press kits.
* Organization JSON-LD with name, url, logo, description, email, sameAs[]
  pointing only at real official profiles (THIRD_PARTY_PROFILES). Never invent URLs.
* SoftwareApplication (or Product) schema for SaaS: category, offers, provider.
* Person schema / clear founder byline (FOUNDER_OR_AUTHOR) on guides and About.
* Consistent spelling of PRODUCT_NAME everywhere (no alternate brand spellings).
* About page with concrete facts: what you are, who for, founding story, contact.
* Prefer server-rendered HTML for hero + answer blocks (AI crawlers are weak at JS).

───────────────────────────────────────────────────────────────────
B2. Technical crawl access for AI engines
───────────────────────────────────────────────────────────────────

* Allow AI crawlers in robots.txt unless you have a deliberate block policy.
  At minimum do not accidentally disallow: GPTBot, OAI-SearchBot, ChatGPT-User,
  ClaudeBot, anthropic-ai, PerplexityBot, Google-Extended, Applebot, Bingbot.
* Submit sitemap to Google Search Console AND Bing Webmaster Tools
  (ChatGPT Search leans on Bing; AI Overviews/Gemini lean on Google).
* Optional IndexNow if you publish often.
* Clean canonicals; HTTPS; fast LCP; no paywall on pages you want cited.
* Visible last-updated / dateModified on money + guide pages; keep schema dates honest.
* Serve /llms.txt at SITE_URL/llms.txt following https://llmstxt.org :
  H1 = product name; blockquote = ONE_LINER + key facts; H2 sections with
  curated markdown links to authoritative pages (pricing, features, compare,
  guides, security). Auto-generate from your content registry so it never drifts
  from the sitemap. llms.txt is a map for agents — NOT a substitute for
  robots.txt, sitemap, schema, or real content.
* Optional advanced: markdown mirrors of key docs pages (page.md / Link rel=alternate
  type=text/markdown) when your stack supports it — especially for docs-heavy products.

───────────────────────────────────────────────────────────────────
B3. Page-level extractability (write for citation, not fluff)
───────────────────────────────────────────────────────────────────
GEO section formula (use under every important H2/H3):

1. Heading = the buyer question (or clear topic that matches conversational queries)
2. First 40–60 words = direct answer (no “in this section we will explore…”)
3. Next sentence = strongest supporting fact, number, or named source
4. Body = specifics, examples, edge cases
5. Optional closing implication or CTA (do not bury the answer under the CTA)

Mandatory content patterns

* TL;DR / answer box near the top of guides and commercial pages (40–60 words).
* FAQ sections with exact Q&A visible in HTML (not only accordion empty of text);
  FAQPage JSON-LD matching visible questions (3–7 top questions per page).
* Comparison pages with tables + “Best for” / “Not best for” (AI engines extract tables).
* Concrete capabilities and limits (pricing floors, channels, trial length, what you
  do NOT do). Vague hype is rarely cited.
* Statistics and original numbers when true (your product data, honest benchmarks).
  Prefer “Pro is $29/mo with a 7-day trial” over “affordable pricing.”
* One claim per short paragraph; self-contained 60–100 word blocks.
* Question-form H2s that mirror how people ask ChatGPT/Claude
  (“What is a ManyChat alternative for coaches?” not “Overview”).
* Outbound links to authoritative non-self sources where you cite industry facts
  (models distrust closed loops of self-promotion).

Page types that win GEO (prioritize in this order)

1. Compare / alternative pages (vs COMPETITOR_COMPARE)
2. Category-defining pages (what PRODUCT_NAME is + ONE_LINER)
3. How-to / guides with answer-first intros
4. Pricing with concrete plan facts
5. Integration / use-case pages with setup FAQs
6. Security / trust pages with honest compliance status (no fake certs)

Anti-patterns (do not ship)

* Story-led intros with zero facts
* Keyword stuffing
* Claiming certifications you do not have (hurts trust + citation)
* Hiding answers behind client-only JS
* Duplicate near-identical pages fighting each other (cannibalization)
* Buying fake reviews or spam “citation” links

───────────────────────────────────────────────────────────────────
B4. Off-site corroboration (engines trust the network)
───────────────────────────────────────────────────────────────────
Owned pages alone are not enough. Build a corroboration network:

| Surface                | Why engines care                           | What to do                                       |
| ---------------------- | ------------------------------------------ | ------------------------------------------------ |
| LinkedIn co + founder  | Identity + co-citation                     | About = ONE_LINER; weekly posts with demos       |
| YouTube                | How-to / comparison citations              | 3+ walkthroughs; full transcripts in description |
| G2 / Capterra          | B2B compare queries                        | Complete profile; honest reviews; respond        |
| Crunchbase             | Entity disambiguation                      | Complete company record; add to sameAs when live |
| Product Hunt           | Launch + category tags                     | Clear category; ONE_LINER                        |
| Reddit / IndieHackers  | Perplexity + ChatGPT category queries      | Value-first answers; link only when relevant     |
| Guest posts / podcasts | Third-party co-mention with CATEGORY_TERMS | Earn coverage; do not spam                       |
| X / Twitter            | Helps Grok + social corroboration          | Bio + pinned demo; real conversation             |
| Wikipedia              | Heavy ChatGPT source weight                | Earn via independent coverage; never vanity-edit |

Target: 15–25 meaningful third-party mentions per quarter (quality > volume).
When third parties describe you, they should paraphrase ONE_LINER + CATEGORY_TERMS
so entity↔topic association strengthens.

───────────────────────────────────────────────────────────────────
B5. Engine-specific deltas (same trinity, different retrieval)
───────────────────────────────────────────────────────────────────

* ChatGPT Search: Bing index matters → Bing Webmaster + strong schema + clear entities.
* Google AI Overviews / Gemini: classic Google SEO + FAQ/HowTo-friendly structure;
  top organic relevance still helps.
* Perplexity: aggressive live crawl + heavy citations; favor fresh dateModified,
  clean HTML, allow PerplexityBot; Reddit/community corroboration helps.
* Claude: quality/depth + ClaudeBot access; quoteable passages; llms.txt helps agents.
* Copilot: Bing-oriented; similar to ChatGPT Search hygiene.
* Grok: web + X presence; real posts matter more than corporate boilerplate.

Do not build six separate sites. Build one extractable site + engine-aware distribution.

───────────────────────────────────────────────────────────────────
B6. Measurement (citation ledger — non-negotiable)
───────────────────────────────────────────────────────────────────
AI answers are non-deterministic. One screenshot is noise. Run a ledger:

For each prompt in GEO_WEEKLY_PROMPTS, weekly, across GEO_TARGET_ENGINES, log:

* date
* engine + mode (e.g. ChatGPT with search on/off)
* prompt text (exact)
* brand mentioned? (yes/no)
* linked? (yes/no)
* which URL/passage was cited (if any)
* competitors named
* notes / screenshot link

Track two rates over a rolling window (e.g. 4 weeks):

* Present-rate: % of runs where an AI Overview / answer container appears (if applicable)
* Cited-rate: % of runs where PRODUCT_NAME is named when an answer appears

Act on gaps: if a prompt is consistently uncited, improve the matching page’s
answer block, FAQ, compare table, or earn a corroborating mention — then retest.

Also wire product analytics (ANALYTICS) for AI-referred traffic when UTM/referrers
exist (chatgpt.com, perplexity.ai, etc.) — separate from classic organic.

───────────────────────────────────────────────────────────────────
B7. Freshness cadence
───────────────────────────────────────────────────────────────────

* Compare + pricing: review monthly (facts, prices, “best for”)
* Guides: quarterly refresh + bump visible updated date when material
* llms.txt: regenerate from registry on each request or on content publish
* After each new money page: confirm sitemap + llms.txt + GSC/Bing URL inspection

  * share founder post + re-run 2–3 related GEO prompts
